📝 Data Hazards Topic 4

The 1-Sentence Story: Data hazards occur when an instruction depends on the result of a previous instruction that hasn't finished yet; they are solved through hardware stalling, operand forwarding, or compiler-based scheduling to maintain correct execution order.

📌 Definitions & Key Terms

Data Hazard
A condition where an instruction depends on the result of a previous instruction that has not yet completed its execution.
RAW
Read-After-Write: instruction j reads an operand before instruction i writes it. (Most common hazard).
WAW
Write-After-Write: instruction j writes an operand before instruction i writes it. (Only in out-of-order pipelines).
WAR
Write-After-Read: instruction j writes an operand before instruction i reads it. (Only in out-of-order pipelines).
Operand Forwarding
(Bypassing): technique to resolve RAW hazards without stalling by forwarding the result directly from one pipeline stage to another.
Side Effect
An instruction changes a register or flag other than its explicitly named destination (e.g., condition code flags, autoincrement, stack pointer).

🔗 The RAW Hazard Problem (Example)

I₁: MUL R2, R3, R4  // writes R4 in W₁
I₂: ADD R5, R4, R6  // reads R4 in D₂
  • Problem: I₂ reaches Decode before I₁ finishes Write-back. I₂ reads the old value of R4.

🛠️ Solutions for Data Hazards

🧱 Pipeline Stalling (Hardware)

Detect the hazard and freeze the pipeline (insert bubbles) until the data is ready.

  • Disadvantage: wastes clock cycles, reduces throughput.
✔ simple but costly

↪️ Operand Forwarding / Bypassing (Hardware)

Forward the result directly from the ALU output (E stage) to the next instruction's ALU input (E stage).

  • Paths: E → E (most common), W → E (when result isn't ready in time for E → E).
  • Advantage: eliminates stalls for most RAW hazards.
  • Limitation: cannot solve the Load-Use hazard (requires one stall cycle).
✔ best for most RAW hazards

🧠 Compiler-Based Scheduling (Software)

NOP Insertion: compiler inserts No-Operation instructions to delay the dependent instruction.

Instruction Reordering: compiler moves independent instructions into the delay slots to do useful work.

  • Advantages: simplifies hardware, compiler can optimize.
  • Disadvantages: increases code size, may reduce performance on processors with better hazard handling.
📖 software-level fix

⚠️ Load-Use Hazard (Why Forwarding Fails)

I₁: LOAD R1, [Address]  // data available only after Memory stage
I₂: ADD R2, R1, R3  // needs data in Execute stage

The data arrives too late for I₂'s Execute stage, so one stall cycle is required.

🧩 Side Effects (Hidden Dependencies)

  • Condition Code Flags: ADD modifies the Carry Flag; ADDC uses it.
  • Autoincrement/Autodecrement: LOAD R1, (R2)+ implicitly modifies R2.
  • Stack Operations: PUSH/POP implicitly modify the Stack Pointer (SP).

Impact: increases hazard detection complexity; design guideline is to minimize side effects.

📌 KEY EXAM POINTS
RAW is the most common data hazard in a basic 5-stage pipeline.
WAW & WAR only occur in out-of-order pipelines.
Forwarding resolves most RAW hazards without stalling.
Load-Use hazard requires one stall cycle even with forwarding.
Compiler scheduling (NOPs, reordering) is the software solution.
