📝 Control / Instruction Hazards Topic 5

The 1-Sentence Story: Control hazards occur when branch instructions change the program flow, causing the pipeline to fetch wrong-path instructions that must be flushed; they are mitigated through instruction queues, delayed branching, and static/dynamic branch prediction.

📌 Definitions & Key Terms

Control Hazard
(Instruction Hazard): a delay caused by a branch or jump instruction that changes the program counter, disrupting the steady flow of instructions.
Branch Penalty
The number of clock cycles wasted when a branch is taken and incorrectly fetched instructions are discarded.
Delay Slot
The instruction slot immediately after a branch, which is always executed (filled with a useful instruction or NOP).
Static Branch Prediction
A fixed prediction (e.g., always not taken, or compiler-provided hint).
Dynamic Branch Prediction
Hardware-based prediction that adapts based on the branch's history (1-bit or 2-bit predictors).
Speculative Execution
Executing instructions along the predicted path before the branch outcome is confirmed.

🤔 Why Branches Hurt Pipelines

  • Branches represent about 20% of dynamic instructions.
  • The branch target/decision is often unknown until the Execute stage.
  • The pipeline has already fetched sequential instructions (wrong path).
  • Those instructions must be flushed (discarded), wasting cycles.

📉 Branch Penalty and Pipeline Depth

Pipeline Depth Cycles Lost
2-stage pipeline 1 cycle lost
4-stage pipeline 2 cycles lost
  • Deeper pipelines = larger penalties.

🛠️ Solutions for Control Hazards

📥 Instruction Queue & Branch Folding

  • Fetch unit prefetches instructions into a queue.
  • Dispatch unit takes instructions from the queue.
  • Even during stalls, Fetch continues to fill the queue.
  • Branch Folding: if the queue already contains the correct target instruction, the branch executes with zero penalty.
  • Benefit: smooth instruction supply, reduced visible stalls.

⏳ Delayed Branching

  • The instruction immediately after a branch (the delay slot) is always executed.
  • Compiler fills the delay slot with a useful, independent instruction.
  • If no useful instruction can be found, a NOP is inserted.
  • Effectiveness: one delay slot is usable about 85% of the time. Two delay slots are much harder to fill.
  • Trade-off: fewer stalls vs. increased compiler complexity.
BEQZ R2, NEXT
ADD R3, R4, R5  // delay slot — always executed

📌 Static Branch Prediction

  • Always assume not taken (simple default).
  • Compiler/hardware hint: a prediction bit is included in the branch instruction (e.g., SPARC).
  • Backward branches (loops): usually predicted taken.
  • Forward branches (if-then-else): usually predicted not taken.
  • Speculative execution: instructions along the predicted path are executed before the branch is confirmed.
  • If prediction is wrong: instructions are flushed, and the pipeline restarts.

🧠 Dynamic Branch Prediction

  • 1-bit predictor: two states (LT/LNT). Predicts based on the previous outcome. Flips immediately on a misprediction.
  • 2-bit predictor: four states (ST, LT, LNT, SNT). Requires two consecutive mispredictions before flipping. More stable and accurate.
  • Advantage: adapts to actual program behavior, higher accuracy than static prediction.
1-bit: LT ↔ LNT 2-bit: ST → LT → LNT → SNT
📌 KEY EXAM POINTS
Control hazards are caused by branches/jumps that change the program counter.
Branch penalty increases with pipeline depth.
Instruction queue decouples Fetch from Execute, reducing stalls.
Delayed branching fills delay slots with useful instructions.
Static prediction uses fixed rules; dynamic prediction learns from history.
Speculative execution executes along the predicted path; wrong predictions are flushed.
